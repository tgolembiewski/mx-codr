Everything the mx-codr harness does

An AI agent builds the Mendix app with mxcli. The harness gives it one short rule file it reads on every turn, eleven skills it reads when a part of the app calls for one, and a starter kit for its Playwright tests. One thing runs while the agent builds, in Claude Code and (in the Studio Pro extension) Codex: the skill gate, which refuses a model change or a test file until the project skill for it was read whole. No other gate, no verdict.

1What it is

38 + 26lines in the always-on rule file (the rule, then the brain rule)
11skills installed beside mxcli's
5files in the starter test kit
1gate that runs while the agent builds: the skill gate (Claude Code; Codex in the extension)
  • The source is mxcodr/ in this repository: install.sh, the installer overlay/install.mjs, the rule file and the kit in overlay/templates/, the skills in overlay/skills/.
  • The agent proves its own work with tests it keeps in tests/; whether a run built what was asked is measured from outside, by harness-eval/.
  • v1 (the gate tests/gate.sh, hooks, checkers and the rulebook) was removed on 2026-11-01 and is kept in the tags v1-best-hb1 and v1-last.

2The rule file

overlay/templates/mxcodr.md, installed word for word for Claude Code; Cursor gets the same text under its own frontmatter, Codex, opencode and Pi get it as a block in AGENTS.md with their skills folder named instead. GitHub Copilot CLI (in the Studio Pro extension) reads the Claude Code copy in .claude/rules/ as it is. The extension writes that copy also when the person removed Claude Code from its agents (Claude Code is one choosable agent since 2026-11-12; at least one stays).

18# Keep your checks as tests
19
20Every check you make of the running app — a browser flow per role, a refusal, data isolation, a
21computed value, an API call — goes into `tests/` as a re-runnable automated test (Playwright for the
22browser), never a throwaway script. Each requirement of the request gets a test that asserts its actual
23content (the value, the order, the refusal, both sides of a rule), not only that a page opens. Before you
24say you are done, run the whole suite once and show it passing.
25
26Write them as plain `@playwright/test` specs on top of `tests/mx.ts` (sign-in and sign-out, dialogs, grids, OQL, forged calls; take `test` and `expect` from `./mx`), with your own helpers beside it, and sign out at the end
27of each test (the trial runtime allows six sessions). Prove a refusal by attempting the forbidden action
28as that role (a call, a URL, an API request) and asserting that the server refuses it, plus the allowed
29side as the permitted role; never add a button, widen access or lower security so a test can see a message.
30Write and run the tests yourself in the foreground, never through a background agent, and never end your turn while a test run or an agent is still going. **You are done only
31when** you have printed a table `requirement -> test that asserts it` covering every requirement of the
32request (write the missing tests first), then run the whole suite once as `npx playwright test --shuffle`
33in `tests/` and shown it green with `sessions left: 0`. Never edit `tests/mx.ts`, `tests/mx-impl.ts` or
34`tests/mx.teardown.ts` to silence a check; fix the leaking test. Stop the app with
35`./mxcli run stop`, and any other process only by the exact PID you started, never by a name pattern
36(`pkill`, `killall`): that also kills the person's own browsers and test runs.
37
38Never add a document to a Marketplace module (`list modules`: Source `Marketplace v...`) or change one in it: its next update deletes the addition and undoes the change; the app's documents go in its own module, a changed copy in `<Module>Ext`. Marketplace widgets only from publisher Mendix or Mendix Labs. Once `docs/app-docs.html` exists, update it with the `app-docs` skill at the end of every turn that changed the model, before you report.

The brain rule (since bundle 2026.11.14.1)

overlay/templates/brain.md, appended after one empty line to every shape of the rule text (ruleText in overlay/lib/rules.mjs, after the coverage, live and switched-off-skills edits, which never see it): .claude/rules/mxcodr.md, the .mdc, the AGENTS.md block, and so Copilot's read of .claude/rules/ and the extension's live setup. 26 lines, 2,447 characters, about 610 tokens; its size test allows 26 lines and 2,450 characters (2,400 until bundle 2026.11.18.9, 2,300 until 2026.11.18.7; 2026-11-14: every entry is a title of about 8 words with its details on the second line, plan lines take a | why part, decisions are numbered D<n>; earlier, after real plans: a requirement is one short sentence naming the outcome; in plan mode a business-rule answer goes into the plan's lines, no --open; a requirement's anchor is new work, a new slice takes the next free number, a plan's business-rule assumptions are Decision lines, and a finding's second line is the why the person decides by). It carries the owner-approved contract of 2026-11-14 between the agent and mx-codr's panel: the agent only proposes (./mxcli brain capture ... --json), on three checkable triggers; the panel (the Studio Pro extension, which sets MXCODR_PANEL=1 for every agent it starts) approves, and gives the session-start brain pack that replaces reading docs/brain/ (and mxcli's "Project Brain" section in CLAUDE.md/AGENTS.md). Without the panel the person approves in the chat and the agent keeps mxcli's own reading.

2bThe skill gate (since bundle 2026.11.18.2, Claude Code; since 2026.11.18.6 also Codex in the Studio Pro extension)

overlay/lib/skill-gate.mjs: two Claude Code hooks in .claude/settings.local.json (which mxcli init never overwrites, unlike settings.json) that hold the agent to lines 1-16 of the rule file. Nothing else of v2 refuses anything.

  • PostToolUse on Read|Skill: a read of .claude/skills/<name>/SKILL.md (or .ai-context/skills/<name>/SKILL.md) with no limit, or a limit that covers the file, or the Skill tool loading it, records <name> in .mxcodr/state/skills-read-<session>/<name>, one empty file per skill so Reads run in parallel all count (git-ignored; a week-old record of another session goes; a SKILL.md outside the app does not count). A part, a cat or a head does not count.
  • PreToolUse on Bash|PowerShell|Write|Edit|MultiEdit: ./mxcodr-live exec, mxcli exec and mxcli -c are classified by their MDL (the script file the command names, else the command's own text such as a heredoc; comments, quoted strings and Java bodies left out, case ignored): a new module, folder, move or document of any kind needs module-structure and naming-and-captions; module or user roles, grants, revokes, access rules, demo users, project security: app-security; pages, snippets, layouts, navigation: spacing-and-layout and naming-and-captions; System.FileDocument or System.Image, upload and image widgets: files-and-images; a Java action: java-action-docs. A write of tests/**/*.spec.ts needs durable-tests. Check, query, show and describe are never gated.
  • A needed skill not read yet in this session (and present in .claude/skills/: a switched-off one is not asked for) refuses the call, exit 2, with: mx-codr skill gate: This model change needs the project skills below, not read yet in this session. Read each file whole with the Read tool (no offset or limit, one file per read, never cat or head), then check your script against them and run the same call again: followed by each SKILL.md's full path and what it is for, and These project skills come before `./mxcli syntax` and before mxcli's own skills in .ai-context/skills/.
  • After a compaction (since bundle 2026.11.20.1) the model has only a summary of the skills it read, so skill-gate.mjs reset clears .mxcodr/state/skills-read-<session>/ for that session only (other sessions keep theirs; it prints nothing and always exits 0): Claude Code runs it on SessionStart with matcher compact (same session_id, measured on Claude Code 2.1.326), written by the installer and the extension's setup beside the two gate hooks and replaced, never doubled, on a reinstall; Codex runs it on PreCompact in the extension's .codex/hooks.json (accepted and trusted by Codex 0.167.0; that it fires is not measured yet). Pi has no gate.
  • It fails open: bad input, a script it cannot read, a state folder it cannot write (a link, read-only), no Node: the call runs. MXCODR_SKILL_GATE=0 in the environment Claude Code starts in switches it off.
  • File mode: the installer copies it to .mxcodr/skill-gate.mjs and registers node "$CLAUDE_PROJECT_DIR/.mxcodr/skill-gate.mjs" pre|post (removed again when Claude Code is not among the agents). Live mode: run from the extension's verified runtime, never from the app. Cursor, opencode, Pi and Copilot read the same rule text without the gate; Codex has it only in the extension (below).
  • Codex (since bundle 2026.11.18.6; the extension's setup writes two entries into .codex/hooks.json, matcher *, beside the git and sed guards and trusted with them: sh '<runtime>/live/translator/bin/guard.sh' skill-gate pre|post --agent=codex, on Windows <runtime>\live\translator\bin\skill-gate.cmd pre|post --agent=codex, which reads the line as PowerShell and fails open without a Node). Measured with Codex 0.167.0: its hooks get tool_name Bash for exec_command (only {command}, no max_output_tokens) and apply_patch (the patch as command); PostToolUse's tool_response is the output as the model sees it, with Codex's marks when it was cut (Warning: truncated output (original token count: N), …N tokens truncated…); a code-mode exec cell gets no hook, has its own 10,000-token budget (first line // @exec: {"max_output_tokens": N} raises it), and is in transcript_path before its commands' hooks run, its output before the next cell's; exit 2 with the reason on stderr blocks a nested command and an apply_patch (the model sees Command blocked by PreToolUse hook: <reason>). The measured miss it closes: CarFleet's session read three skills in one cell with Promise.allSettled, each command's output whole, the cell's cut from 12,236 to 10,000 tokens; most of spacing-and-layout never arrived and 26 buttons had no spacing.
    Post: one command that reads one gated SKILL.md in .agents/skills/ or .claude/skills/ inside the app (cat, nl, type, Get-Content; or lines: sed -n 'A,Bp', head -n N, tail -n +K, Get-Content -TotalCount N, piped sed -n or Select-Object -Skip/-First), its output without a truncation mark and showing the range's last line, is recorded with the cell it ran in. Pre: a recorded read counts once its cell's output is in the transcript without a mark and with that line (a read and a write in one cell do not count; a cut cell's reads are forgotten); ranges count once they cover the file; a transcript that cannot be read leaves the command's own check. Gated as for Claude Code: model writes in shell commands, and tests/**/*.spec.ts added, updated or moved to by apply_patch (or a patch given to a shell command). The deny: mx-codr skill gate: This model change needs the project skills below, not read whole yet in this session. Read each file in its own command, one file per command (never several files in one call, never Promise.all or a loop): in an exec script start with the line // @exec: {"max_output_tokens": 30000} and give exec_command max_output_tokens: 30000 (cat <file>; on Windows Get-Content -Raw <file>). 4The starter test kit

overlay/templates/tests/, copied into the app's tests/ when a file is absent. A later install replaces a kit file only when its text is one mx-codr shipped before (overlay/lib/kit-shipped.json: the sha256 of every past version, CRLF read as LF), so a fix in the kit reaches apps installed earlier; a file the person or the agent edited is never overwritten, and the installer names it once (and records it as testKitEdited).

Specs import test, expect and the helpers from ./mx. Agents read this file whole whatever a skill says, so it holds only what a spec needs.
