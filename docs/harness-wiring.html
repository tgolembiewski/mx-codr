How the harness is wired

Read left to right: a person installs once, the files land in the app, the agent reads one rule file on every turn and a skill when a part of the app calls for one, and keeps its checks as tests. Nothing is wired into the agent's tools: no hook fires, no command is wrapped, no verdict is printed into its context.

1 · The person

mxcli new <App>
bash mxcodr/install.sh <app>

Once per app; again to upgrade or repair.

2 · The installer

overlay/install.mjs

Pins mxcli 0.29.0, applies the chosen look (theme/ only), caches MxBuild and the runtime, removes earlier bundles' files, writes ours, then syncs mxcli's skills.

3 · Files in the app

rule file · skills · tests/mx.ts … · .mxcodr/

Plain files the agent's own host loads; no settings, no hooks.

4 · The agent

./mxcli exec · ./mxcli run · npx playwright test

Builds with mxcli, boots the app, runs its suite, shows it passing.

5 · Measured outside

harness-eval/bin/run.sh · score.py · check_<prompt>.py

An independent check the agent never sees, after the run.

The AGENTS.md block is written only for Codex, opencode or Pi, so Cursor alone does not read the text twice. Every agent gets the same starter kit in tests/ and .mxcodr/installed.json.

What reaches the agent's context

Every turn

The 25-line rule file: keep checks as tests, prove refusals by attempt, finish only after a requirement-to-test table and one green shuffled run with no session left, stop processes by PID, and which skill covers which part.

On demand

A skill's SKILL.md when the rule file or its description sends the agent there, and its reference/ files when the skill points to them. The kit's tests/mx.ts when the agent writes a spec.

Never

Nothing is injected: no hook output, no gate verdict, no wrapped mxcli. What the agent sees from mxcli is mxcli's own output.

Kept by the installer

--request <file> saves the request word for word as docs/requests/NN.md; the agent reads it like any file.

How a run is measured

  • AGENT=claude MODEL=claude-sonnet-5-5 bash harness-eval/bin/run.sh <prompt> <label>: mxcli new, then install.sh <app> --db hsqldb --agent <agent> --request prompt.txt, then the agent unattended.
  • After the agent ends, the app is restarted with ./mxcli run stop and ./mxcli run --local and score.py adds one line to harness-eval/results/results.jsonl: time, tokens, turns, scope, test files, and the checks of check_<prompt>.py.
  • The run's transcript and logs stay in harness-eval/results/runs/; a written report goes to docs/sessions/<date>-<name>/.
