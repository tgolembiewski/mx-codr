How the harness steers an AI agent

The agent writes the Mendix app. The harness sits around it: hooks the agent's host fires on every prompt and command, scripts in tests/ that boot, test and judge the app, and rules the agent reads. Pick a moment, press Play, and watch which file calls which — and, on the right, the exact text that lands in the agent's context. Every hook and script text is real output of harness 2026.10.10.3, captured on a running invoicing app or taken from a recorded Pi session; what the agent itself writes is shown as a short example.

Three ideas to remember

The model is never changed blind

Every mxcli exec is first tried on a copy of the model with Mendix's own mx check. A script that would break the build is stopped before it runs.

Only the gate says "done"

bash tests/gate.sh runs the browser tests and ten model checks. It ends in DONE or NOT DONE, with the fix for each finding under the verdict.

The agent cannot move the goalposts

guard-harness-env.sh refuses edits to the gate's scripts, the rule cards in tests/rulebook/ and tests/harness.env. The session may not change what judges it.
